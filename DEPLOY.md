# Развёртывание на своём сервере

Требуется: Ubuntu 22.04/24.04 или Debian 12, Python 3.11+ (либо Docker),
не менее 1 ГБ памяти и выход в интернет.
Бот только опрашивает сайт и Telegram — открытых портов и домена не нужно.

Это краткая версия — для тех, кто уже разворачивал похожие сервисы. Если нужны
пошаговые команды с ожидаемым выводом на каждом шаге, смотрите
[УСТАНОВКА.md](УСТАНОВКА.md).

## Шаг 0. Адрес API определяется автоматически

Отдельно искать и переносить адрес больше не нужно. При первом запросе бот сам
запускает headless-Chromium, наблюдает сетевые ответы карты и запоминает найденный URL
до перезапуска процесса.

После установки можно проверить автопоиск командой:

```bash
python cli.py --available
```

## Шаг 1. Токен

Получите токен у [@BotFather](https://t.me/BotFather) и впишите в `.env`:

```bash
cp .env.example .env
nano .env                     # BOT_TOKEN=123456:AA...
```

## Шаг 2А. Установка через systemd (рекомендуется)

```bash
scp -r gpn_fuel_bot/ user@server:/tmp/
ssh user@server
sudo bash /tmp/gpn_fuel_bot/deploy/install.sh
```

Скрипт проверит версию Python, создаст системного пользователя `gpn`, развернёт
виртуальное окружение, установит Chromium в доступный сервису каталог, проверит его
запуск от пользователя `gpn` и запустит сервис. Скрипт идемпотентен — повторный
запуск просто обновляет код и перезапускает бота.

Отказывается работать, если `BOT_TOKEN` пуст или остался заглушкой из примера, — чтобы
сервис не «поднялся» в нерабочем состоянии.

```bash
journalctl -u gpn-bot -f      # логи
systemctl restart gpn-bot     # перезапуск
systemctl stop gpn-bot        # остановка
```

База лежит в `/var/lib/gpn/gpn.db` — обновление кода её не трогает.

## Шаг 2Б. Установка через Docker

```bash
docker compose up -d --build
docker compose logs -f
docker compose ps
```

Playwright и Chromium входят в образ и используются только тогда, когда обычные
способы найти API не сработали. Подписки и история живут в томе `gpn-data` и
переживают пересборку.

В образ встроена проверка здоровья: если данные не обновлялись дольше 30 минут,
контейнер помечается как `unhealthy` — это видно в `docker ps`.

Для первого запуска Docker обычно требуется 1–2 ГБ свободного места: Chromium и его
системные библиотеки входят в образ.

## Обновление

```bash
# systemd
sudo bash /tmp/gpn_fuel_bot/deploy/install.sh

# docker
docker compose up -d --build
```

## Резервная копия

Вся ценность — в одном файле с подписками и историей:

```bash
sudo sqlite3 /var/lib/gpn/gpn.db ".backup '/root/gpn-$(date +%F).db'"
# docker:
docker compose exec bot sqlite3 /data/gpn.db ".backup '/data/backup.db'"
```

## Настройки

Полный список — в `.env.example` и в README. Проверить, что всё задано верно:

```bash
cd /opt/gpn_fuel_bot && .venv/bin/python config.py
```

Утилита покажет действующие настройки (токен маскируется) и объяснит проблемы, если
они есть. Она же встроена в `install.sh`, поэтому сервис не установится с нерабочим
токеном.

Если `api.telegram.org` недоступен из сети сервера, укажите свой Bot API сервер
(`BOT_API_URL`) или прокси (`BOT_PROXY`) — остальное соберётся само.

`POLL_INTERVAL` меньше 120 секунд автоматически поднимается до минимума: сайт чужой
и публичный, частые запросы приведут к блокировке IP сервера.

## Если что-то пошло не так

**Сервис не стартует** — `journalctl -u gpn-bot -n 50`. Чаще всего пустой `BOT_TOKEN`.

**В логах «Не удалось получить данные АЗС»** — автоматический поиск не смог открыть
карту или сайт ограничил доступ. Проверьте доступ с IP сервера; для диагностики
запустите `.venv/bin/python discover.py --verbose`. URL можно временно указать через
`GPN_API_URL`.

**Бот отвечает, но список АЗС пуст** — сайт отдал данные в новой схеме либо изменил
фильтрацию. Запустите `python cli.py --all-regions` и посмотрите, приходит ли вообще
что-нибудь; при необходимости `python discover.py --dump` сохранит сырые ответы для
разбора.

**Уведомления не приходят** — первый прогон их не шлёт по замыслу: он только фиксирует
базовое состояние. Уведомление уходит на переход статуса, а не на каждый опрос.
