# Мониторинг топлива на АЗС «Газпромнефть» — Краснодарский край

Парсер карты `gpnbonus.ru/fuel/refuel-map` + Telegram-бот, который присылает
уведомление, когда нужная марка топлива появляется в наличии.

## Что важно знать перед запуском

**Адрес API сайта в коде не зашит.** При первом обращении клиент проверяет известные
варианты, содержимое страницы, а затем при необходимости открывает карту в
headless-Chromium и сам находит нужный сетевой запрос. Найденный адрес хранится только
в памяти процесса: создавать или переносить `endpoint.json` не требуется.

Разбор ответа намеренно сделан устойчивым к схеме: JSON обходится рекурсивно, объекты
АЗС и списки топлива опознаются по набору полей. Проверено на трёх разных формах
ответа (плоский список со строковым статусом, GeoJSON с `[lon, lat]` и булевым
наличием, вариант другого региона) — `python test_parser.py`.

## Установка

Локальный запуск для разработки и проверки — ниже. **Для установки на сервер** есть
отдельные инструкции: [DEPLOY.md](DEPLOY.md) — кратко, для тех, кто уже разворачивал
подобные сервисы; [УСТАНОВКА.md](УСТАНОВКА.md) — пошагово, с ожидаемым выводом на
каждом шаге, для тех, кто делает это впервые.

```bash
pip install -r requirements.txt
playwright install chromium

python cli.py --available          # адрес API определится автоматически
python discover.py                 # необязательная ручная диагностика
#   --show   показать окно браузера (если карта не грузится в headless)
#   --dump   выгрузить сырые ответы в sample_*.json для изучения схемы
```

Если `discover.py` ничего не нашёл, откройте карту в браузере → DevTools → Network →
фильтр Fetch/XHR, найдите запрос со списком АЗС и укажите его вручную:

```bash
export GPN_API_URL="https://gpnbonus.ru/api/..."
```

## Telegram-бот

```bash
cp .env.example .env      # вписать BOT_TOKEN от @BotFather
export $(grep -v '^#' .env | xargs)
python bot.py
```

Управление кнопочное — команды набирать не нужно. Внизу экрана постоянное меню:

```
[🔍 Найти АЗС]
[⛽️ Моя АЗС]     [🔎 Где есть топливо]
[⛽ Бензин в наличии]
[🔔 Подписки]    [❓ Помощь]
```

**Найти АЗС.** Открывается список городов кнопками — Краснодар, Сочи, Новороссийск,
Анапа, Армавир, Кропоткин, Ейск, Геленджик. Если нужного нет, достаточно просто
написать адрес сообщением: любой текст воспринимается как поисковый запрос, команда
не нужна. Длинные списки листаются кнопками ◀️ ▶️ по 8 штук.

**Карточка АЗС.** Кнопка на каждую марку: слева наличие, справа слежение.

```
[✅ 92 🔕]      [❌ 95 🔔]
[❌ G-100 🔕]   [❌ G-95 🔕]
[❌ ДТл 🔕]
[🔄 Обновить]   [📜 История]
[🗺 На карте]   [🧭 Маршрут]
[🏠 Меню]
```

Нажатие на марку включает или выключает уведомление и сразу перерисовывает клавиатуру.
Выбранная АЗС запоминается — кнопка «⛽️ Моя АЗС» возвращает к ней в один тап, и выбор
переживает перезапуск бота.

**Где есть топливо** — марки показываются кнопками (список берётся из реальных данных,
а не зашит в код), дальше сразу список АЗС, где марка в наличии.

**Подписки** — каждая строка это кнопка, нажатие снимает слежение. Никаких `/untrack`.

В уведомлении о появлении топлива тоже есть кнопка «⛽️ Открыть АЗС» — сразу к карточке.

Из команд остались только псевдонимы `/start`, `/help`, `/find`, `/status`, `/list` —
на случай, если кому-то привычнее. Всё то же самое доступно кнопками.

## Настройки

Все параметры собраны в `config.py` — по коду `os.getenv` не размазан. Два блока:
`BotConfig` (всё про Telegram Bot API) и `AppConfig` (опрос сайта и хранилище).

Перед запуском настройки можно проверить, не поднимая бота:

```bash
python config.py
```

Выведет действующие значения и, если что-то не так, объяснит что именно:

```
Telegram Bot API
  токен              123456789:AAHd…Dsaw
  адрес API          http://127.0.0.1:8081
  локальный сервер   да
  ...
Опрос сайта и хранилище
  интервал опроса    120 с  ⚠️ поднято до минимума

✅ Настройки корректны
```

Токен в выводе и в логах **всегда маскируется** — видны только id бота и по четыре
символа с краёв. Эта же проверка встроена в `deploy/install.sh`: сервис не установится
с нерабочими настройками.

### Telegram Bot API

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `BOT_TOKEN` | — | токен от @BotFather, обязателен |
| `BOT_PARSE_MODE` | `HTML` | разметка сообщений |
| `BOT_API_URL` | официальный | свой Bot API сервер |
| `BOT_API_LOCAL` | авто | режим `is_local` для своего сервера |
| `BOT_PROXY` | — | `http://`, `https://` или `socks5://` |
| `BOT_REQUEST_TIMEOUT` | `60` | таймаут запроса к API |
| `BOT_POLLING_TIMEOUT` | `30` | длительность long polling |
| `BOT_DROP_PENDING` | `1` | пропускать обновления, накопленные при простое |
| `BOT_SEND_DELAY` | `0.05` | пауза между сообщениями рассылки |
| `BOT_MAX_RETRY_AFTER` | `300` | предел ожидания по лимиту Telegram |
| `BOT_SEND_RETRIES` | `2` | повторов при сбое отправки |
| `BOT_ADMIN_IDS` | — | id администраторов через запятую |
| `MAX_SUBS_PER_USER` | `30` | лимит подписок |
| `ALERT_ON_GONE` | `1` | уведомлять, когда топливо закончилось |

**Свой Bot API сервер** пригодится, если `api.telegram.org` недоступен из сети сервера
или нужны повышенные лимиты. Достаточно указать `BOT_API_URL` — сессия aiogram
соберётся сама, режим `is_local` включится автоматически. Прокси задаётся так же одной
переменной; если ни то, ни другое не задано, лишняя сессия не создаётся.

### Опрос сайта и хранилище

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `POLL_INTERVAL` | `300` | секунд между опросами |
| `GPN_DB` | рядом с кодом | путь к базе |
| `GPN_API_URL` | определяется автоматически | необязательный адрес API вручную |
| `HISTORY_LIMIT` | `60` | записей истории на марку |
| `PAGE_SIZE` | `8` | АЗС на странице списка |

`POLL_INTERVAL` меньше 120 секунд **автоматически поднимается до минимума** и пишет
предупреждение в лог. Это защита от блокировки IP: сайт чужой и публичный.

## Как запоминается статус

Таблица `fuel_state` хранит текущее состояние, `fuel_history` — журнал **изменений**
по каждой марке отдельно. В журнал попадает и самое первое наблюдение: без этой
базовой записи не от чего отсчитывать, сколько топливо уже отсутствует. Если статус
не менялся, новых записей не появляется — журнал не растёт от простого опроса.

Отсюда берётся длительность в уведомлении:

```
✅ 95 появился
⛽️ Краснодар - Кропоткин - граница Ставропольского края (3 км слева),1
💰 71.31 ₽
🕒 по данным на 12:51 МСК (2 мин назад)
⏳ до этого не было 3 ч 20 мин
```

История подрезается до 60 записей на марку после каждого опроса, чтобы база не росла
бесконечно.

Отдельная деталь — кнопки. `callback_data` в Telegram ограничен 64 байтами, а id АЗС
может быть длинным, поэтому в таблице `tokens` каждому id сопоставлен короткий
числовой токен: `t:1:G100` вместо всего идентификатора. Токены постоянные, так что
кнопки в старых сообщениях продолжают работать после перезапуска.

## Ссылки на Яндекс Карты

У каждой АЗС есть ссылка: в тексте статуса, кнопками под сообщением, в уведомлениях,
в выводе CLI и отдельными колонками в CSV/JSON.

```
[🗺 На карте]   [🧭 Маршрут]
```

**Порядок координат в параметрах Яндекса разный** — это [задокументировано][ym] и легко
перепутать:

| Параметр | Порядок | Пример |
|---|---|---|
| `ll`, `pt` — центр карты и метка | **долгота, широта** | `pt=39.150170,45.018210` |
| `rtext` — точки маршрута | **широта, долгота** | `rtext=45.018210,39.150170` |

Обе формы для одной и той же АЗС в Кропоткине выглядят зеркально. Перепутать их — значит
отправить человека в Ирак вместо Кубани, поэтому порядок закреплён тестом.

[ym]: https://yandex.ru/dev/yandex-apps-launch-maps/doc/ru/concepts/yandexmaps-web

Ссылка выбирается по цепочке приоритетов:

1. **Карточка организации** `/maps/org/{oid}` — если сайт отдал идентификатор
2. **Готовая ссылка с сайта** — если она действительно ведёт на Яндекс
3. **Метка по координатам** — обычный случай
4. **Поиск по адресу** — когда координат нет вовсе

Проверка «яндексовости» ссылки идёт **по домену**, а не по подстроке: `yandex.` встречается
и в `https://evil.example/?ref=yandex.ru`, и в `https://yandex.ru.evil.com/` — обе такие
ссылки отбрасываются, чужой редирект в бот не попадёт.

**Маршрут строится точнее, если прислать геопозицию.** Тогда бот запоминает её и
формирует полный маршрут «откуда-куда» — это документированный формат. Без геопозиции
используется форма с ведущей тильдой (`rtext=~широта,долгота`), которую Яндекс трактует
как «от текущего местоположения»; в официальной документации её нет, поэтому если она
когда-нибудь перестанет работать, рядом всегда есть кнопка «На карте».

Кнопки в Telegram принимают только `http/https`, поэтому deep-link в Яндекс Навигатор
(`yandexnavi://`) не используется — на мобильных обычная ссылка и так открывается в приложении.

## Как это устроено

```
discover.py   автоматическое определение адреса API через Playwright
parser.py     HTTP-клиент, автопоиск API и нормализация JSON в Station/Fuel
config.py     настройки Telegram Bot API и опроса, валидация, python config.py
models.py     Station, Fuel, нормализация кодов топлива
maps.py       построение ссылок на Яндекс Карты (метка, маршрут, поиск, карточка)
storage.py    SQLite: АЗС, состояние и история топлива, подписки, выбор пользователя
bot.py        aiogram 3: кнопочный интерфейс, фоновый опрос и уведомления
cli.py        тот же парсер без Telegram
test_parser.py  проверки нормализации на синтетических ответах
```

Логика уведомлений: каждые `POLL_INTERVAL` секунд данные загружаются заново и
сравниваются с предыдущим снимком в SQLite. Уведомление уходит только на **переход**
статуса (`Отсутствует` → `В наличии`), а не на каждый опрос, поэтому спама нет.
Первый прогон изменений не генерирует — он только создаёт базовое состояние.

## Найденные и исправленные ошибки

Аудит первой версии на реальных краевых случаях выявил пять багов:

| Что было | Почему плохо | Как исправлено |
|---|---|---|
| Статус искался подстрокой | `"10:05"` содержит `"0"` → «отсутствует»; `"Now available"` содержит `"no"` → «отсутствует» | короткие токены (`0`, `no`, `нет`) сравниваются целиком, фразы — вхождением, отрицательные раньше положительных |
| Время статуса разбиралось в строку и нигде не показывалось | нельзя было понять, насколько свежие данные | `parse_site_time()` → `datetime` в МСК, показ возраста и метка «⚠️ устарело» после 60 мин |
| В БД писался нормализованный код | `/status` показывал `G100` вместо `G-100` | отдельная колонка `display_code`; `fuel_code` остался ключом для сравнения |
| Время сайта затиралось временем опроса | смешивались «данные на 12:46» и «мы проверили в 12:49» | разные колонки `site_time` и `checked_at` |
| Майкоп попадал в Краснодарский край | координатная рамка захватывает Адыгею и запад Ставрополья | негативный список регионов; применяется только если в адресе нет кубанского признака |

Плюс мелочи: ссылка на фоновую задачу опроса не сохранялась (сборщик мусора мог её
убить), `json.dump` падал на `datetime`, в `parse_fuel` был недостижимый код.

Регресс на всё перечисленное закреплён в `test_parser.py`.

### Второй аудит

| Что было | Почему плохо | Как исправлено |
|---|---|---|
| Как id Яндекс-организации принимались поля `oid`/`orgId` | внутренний номер сайта подставлялся в `/maps/org/{id}` — ссылка вела на постороннюю организацию, и она была первой в цепочке приоритетов | принимаются только явно яндексовые поля (`yandexOrgId`, `ymapsId` и т.п.) |
| `/track all *` создавал подписку-джокер | одна запись совпадала с любой АЗС и любой маркой, обходя лимит подписок и заваливая уведомлениями | `*` как марка отклоняется с подсказкой |
| В подсказке кнопки показывался нормализованный код | пользователь видел `G100` вместо `G-100` | марка берётся из данных АЗС, ключ остаётся только внутри |
| `prune_history` требовала SQLite ≥ 3.25 | на старых сборках очистка истории падала бы | добавлен запасной путь без оконных функций |
| База создавалась в каталоге проекта | мешает при упаковке и деплое | путь настраивается через `GPN_DB` |

Плюс удалена осиротевшая `fmt_station_line` — она осталась от версии без кнопок.

Проверено: статический разбор на неиспользуемые импорты и недостижимый код, прогон
**каждого** обработчика бота (включая устаревшие кнопки, битые токены, пустые аргументы
и несуществующие АЗС), путь рассылки уведомлений, миграция старой БД.

## Три вида времени — не путать

В выводе фигурируют три разные отметки, и они означают разное:

- **`на 12:46 МСК`** — время самого сайта: когда АЗС последний раз отчиталась об остатках.
  У каждой марки оно **своё** (на скриншоте 95 — 12:46, а 92 — 12:47).
- **`проверено: 12:49 МСК`** — когда бот сам сходил за данными.
- **`→ ориентировочно к 14:46`** — расчёт: время статуса плюс `«еще ~2ч»` из строки доставки.

Всё приводится к МСК независимо от часового пояса сервера. Если отметка старше часа,
рядом появляется «⚠️ устарело» — статус формально «в наличии», но верить ему не стоит.
Отдельно обработан переход через полночь: отметка `23:55`, увиденная в `00:10`,
относится ко вчера, а не к завтра.

Дополнительно учтено:

- `Отсутствует` / `В наличии` / `нет в наличии` / `true` / `1` / `out_of_stock` — всё
  сводится к одному булеву значению.
- Если у марки нет своей отметки времени, подставляется общая по АЗС.
- Порядок координат `[lat, lon]` (Яндекс) и `[lon, lat]` (GeoJSON) различается по
  попаданию точки в границы России, а не по одному лишь диапазону ±90.
- Встроенный в SQLite `lower()` не понимает кириллицу, поэтому для поиска
  зарегистрирована питоновская функция `pylower`.
- Блокировка бота пользователем и `TelegramRetryAfter` при рассылке обрабатываются.
- Регион определяется и по адресу (список городов Кубани), и по координатной рамке.

## Про нагрузку и правовую сторону

Интервал опроса ниже 120 секунд ставить не стоит: это чужой публичный сервис, и
частые запросы с одного IP приведут к блокировке. Данные берутся те же, что видит
любой посетитель сайта, но на всякий случай проверьте актуальные условия
использования gpnbonus.ru, если планируете публичный бот с большой аудиторией.
Сайт может изменить схему ответа или закрыть API — тогда достаточно перезапустить
`discover.py`; правки в коде разбора, скорее всего, не потребуются.
